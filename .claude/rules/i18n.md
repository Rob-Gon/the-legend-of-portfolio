# i18n

## Languages

- Supported: `es` (Spanish), `en` (English). Each language = one folder `public/data/<lang>/`
  with the same seven files.
- **Initial language:** saved preference (`prefs.lang`) → else `es` if any entry of
  `navigator.languages` starts with `es` → else `en`.
- On change: update `<html lang>`, `document.title`, meta description; load (or reuse cached)
  data for the new language; re-render. Save to `prefs.lang`.
- Hash routes are language-neutral (`#/diario/misiones` in both languages).
- Quick mode exists per language: `/quick/` (es) and `/en/quick/` (en), linked with
  `hreflang` alternates.

## Keys (`ui.json`)

- Nested objects grouped by area: `meta`, `title`, `sections`, `tabs`, `tabHints`,
  `weaponPages`, `hints`, `status`, `hud`, `system`, `detail`, `errors`, `journal`, `guide`, `a11y`.
- Keys are camelCase English; values are the translated text.
- Interpolation: `{name}` placeholders → `t('hud.hearts', { years: 2, months: 5 })`.
- Missing key: fall back to the `es` value, then to the key itself; warn once in dev.
- Content texts (quests, projects…) are not keys: they live in each language's content files.

## Adding a language

1. Copy `public/data/es/` to `public/data/<code>/` and translate the values (not the keys,
   ids or language-neutral fields).
2. Add the code to `SUPPORTED_LANGS` in `src/core/i18n.js` and its detection prefix.
3. Add its Quick mode output path to `build/vite-plugin-static-pages.js` and the sitemap.
4. Run `npm test` (the parity test checks every language against `es`).

## Tests

Detection order, fallback, interpolation, `<html lang>` update.

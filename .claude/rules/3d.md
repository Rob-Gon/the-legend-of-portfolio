# 3D

3D is **optional and non-blocking**: everything must work perfectly without it.

## When it loads

- Only if `device.isDesktop` (≥ 1200 px) **and** WebGL is available.
- Loaded with `import('./three/viewer.js')` after the hub is interactive; never in the
  initial bundle. If loading or rendering fails: catch, show the 2D avatar image, toast once.

## Renderer

- **One** `WebGLRenderer` and **one** canvas for the whole app, moved between hosts.
- Render on demand (idle animation at ≤ 30 fps); pause with `IntersectionObserver` when the
  viewer is off-screen and on `visibilitychange` when the tab is hidden.
- `renderer.setPixelRatio(Math.min(devicePixelRatio, 2))`. Dispose geometries, materials and
  textures when swapping models.
- Reduced motion: no idle animation, no auto-rotation; drag-to-rotate still works.

## Content

- **Tech icons:** generated at runtime from the tech's SVG with `SVGLoader` +
  `ExtrudeGeometry` (`model3d: "extrude"` in `tech.json`). No model files.
- **Avatar:** original chibi, big head, Mii-like but not a Mii. Traits from
  `mii.jpg`: black messy hair with fringe, black rectangular glasses, blue headphones around
  the neck, navy hoodie over white tee, light baggy jeans, blue sneakers. Simple idle animation
  and drag rotation (like "Rotate"). Until it exists, use an elegant placeholder (pedestal +
  floating gem).
- The avatar is also rendered to AVIF/WebP for the title screen and tablet/mobile.
- **Hold animation (owner request):** when an Inventory item is selected, the avatar raises its
  arms smoothly (~300 ms blend) and holds the item's 3D icon between its hands; the icon bobs
  gently up and down (a few cm, ~1.5 s loop), like an inventory item in the game. Switching item
  swaps only the held icon. Reduced motion: static hold pose, no bobbing.
- Build the avatar from separate rigid parts (head, torso, upper/lower arms with shoulder and
  elbow pivots, legs) so poses are plain rotations driven from code: no skinning, no
  animation clips needed in the GLB.

## Budgets

| Asset | Budget |
|---|---|
| Any GLB | ≤ 1.5 MB |
| Avatar | ≤ 50 k triangles, ≤ 1 × 1024² texture (WebP) |
| Props (pedestal, gems) | ≤ 5 k triangles each |

## Pipeline: Blender → GLB

1. Model in Blender (via Blender MCP if connected; otherwise the owner provides a file).
   Apply transforms, metres, origin at the feet, Y-up on export.
2. Export glTF Binary (`.glb`) with only the needed animations.
3. Optimise:
   `npx @gltf-transform/cli optimize in.glb out.glb --compress meshopt --texture-compress webp`
   (meshopt, not Draco).
4. Check size and triangle count against the budget, then put it in `public/models/`.
5. Record the source `.blend` outside `public/` (`assets-src/`), committed only if original.

# 3D

3D is **optional and non-blocking**: everything must work perfectly without it.

## When it loads

- Only if `device.isDesktop` (≥ 1200 px) **and** WebGL is available.
- Loaded with `import('./three/viewer.js')` after the hub is interactive; never in the
  initial bundle. If loading or rendering fails: catch, show the 2D avatar image, toast once.

## Renderer

- **One** `WebGLRenderer` and **one** canvas for the whole app, moved between hosts.
- Render on demand (idle animation at ≤ 30 fps); pause with `IntersectionObserver` when the
  viewer is off-screen and on `visibilitychange` when the tab is hidden.
- `renderer.setPixelRatio(Math.min(devicePixelRatio, 2))`. Dispose geometries, materials and
  textures when swapping models.
- Reduced motion: no idle animation, no auto-rotation; drag-to-rotate still works.

## Content

- **Items:** generated at runtime from the selected item's SVG icon (tech logos, own glyphs)
  with `SVGLoader` + `ExtrudeGeometry` (strokes become thin ribbons), in its brand colour.
  No model files (`src/three/items.js`).
- **Avatar:** the owner's likeness (curly black mushroom-cut hair with a fringe, brown eyes,
  a slim nose, a lopsided smirk (thin line laid flush on the face) with one brow raised, nose ring, ear studs) in an adventurer outfit **inspired by** the Twilight
  Princess one (owner's decision, see `assets-ip.md`): green tunic and long cap, cream
  undershirt with a mandarin collar, leather belt and chest strap, leather gauntlets, cream
  trousers, knee-high riding boots with folded cuffs, a jagged tunic hem, chainmail upper arms,
  a belt pouch; a sheathed sword (winged guard) and a riveted shield with three gold triangles on its
  back, so the hands stay free for the held item. Simple stylised look, cel-shaded.
- Modelled in Blender through the Blender MCP (`assets-src/avatar.blend`): Skin + Subsurf
  modifiers for body parts, metaballs for the hair (converted to mesh), simple spheres for the
  face. Exported with modifiers applied and parts merged per pivot and material (≈ 30 draw
  calls) to `assets-src/avatar.raw.glb` (git-ignored), then `npm run model:optimize` →
  `public/models/avatar.glb` (meshopt, ≈ 250 KB, ≈ 52 k triangles, no textures). The pruned
  empty `Hold` node is recreated in code. Head parts hang from `HeadPivot` (idle head turn). Arms hang from empties `Shoulder_L/R` → `Elbow_L/R`; poses are plain
  rotations (`poseAt` in `src/three/avatar.js`, unit-tested); the item floats between the hands.
- The avatar is also rendered from behind (three.js, same toon look, transparent background) to
  `src/assets/scenery/avatar-back.{avif,webp}`: it stands on the cliff of the title scenery
  (desktop only, decorative, lazy).
- **Hold animation (owner request):** when an Inventory item is selected, the avatar raises its
  arms smoothly (~300 ms blend) and holds the item's 3D icon between its hands; the icon bobs
  gently up and down (a few cm, ~1.5 s loop), like an inventory item in the game. Switching item
  swaps only the held icon. Idle (owner request): gentle breathing, a slow weight shift and the
  arms rising slightly with the icon's bob (`poseAt(amount, lift)`). Reduced motion: static hold
  pose, no bobbing, no idle.
- In the viewer, materials become `MeshToonMaterial` (3-step ramp) and a back-face outline is
  pushed out along the normals in the shader (works whatever each part's origin is); face and
  metal materials get no outline.
- The held item has an additive halo sprite behind it, tinted with the item's colour, pulsing
  slowly (static with reduced motion).

## Budgets

| Asset | Budget |
|---|---|
| Any GLB | ≤ 1.5 MB |
| Avatar | ≤ 60 k triangles (owner approved more detail), ≤ 1 × 1024² texture (WebP) |
| Props (pedestal, gems) | ≤ 5 k triangles each |

## Pipeline: Blender → GLB

1. Model in Blender (via Blender MCP if connected; otherwise the owner provides a file).
   Apply transforms, metres, origin at the feet, Y-up on export.
2. Export glTF Binary (`.glb`) with only the needed animations.
3. Optimise: `npm run model:optimize` (`@gltf-transform/cli`, meshopt, not Draco; no
   flatten/join/palette/simplify so pivots and material names survive). The viewer loads it
   with three's `MeshoptDecoder`.
4. Check size and triangle count against the budget, then put it in `public/models/`.
5. Record the source `.blend` outside `public/` (`assets-src/`), committed only if original.
